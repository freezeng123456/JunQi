# 特征与推断逻辑成本盘点（2026-09-11）

比较基线为 `1e327d0c04f25d1b8794664da37a6703f4ed9d28`。范围是环境、信念更新、观察特征及历史存储；不是整个训练系统的性能审计。当前输入为 317 个空间通道和 28 个全局维度。

公开地雷→工兵规则本身不是此次 CPU 测量中的主要瓶颈。主要耗时在战斗记忆展开为平面特征。已删除三类有合法棋局反例的错误推断，保留公共事实和原始战斗历史；没有凭通道数删除尚未验证学习收益的特征组。

## 已执行的精简

- 删除 KILLED 事件中无条件提高隐藏防守者普通军阶下界的逻辑：防守者可能是地雷。
- 删除沿战斗链传播普通军阶下界及据此排除工兵的逻辑：普通棋、雷、工兵之间不满足这种传递关系。链式事件记录仍保留，它不再被解释为传递战力。
- “吃非地雷则不是工兵”收窄为“直接吃掉观察者已知的普通军阶棋”：工兵可以吃军旗。
- CPU 新公开身份只检查本次受影响的存活棋子；初始/恢复构建仍扫描全部棋子。单棋子判断不再构建完整公共地雷矩阵。
- 观察构建的第二次 belief 同步复用已同步结果。384 步、四观察者的 profile 中，同步次数从 3072 降至 1536。
- CUDA 公共身份扫描在现有同步点前缓存一次，四观察者复用；增加 120 字节共享内存，不增加同步点。删除无用的目标 belief 读取。此项只有源码检查，尚未编译或实机测量。

三个新增测试均使用真实 GameState.step 事件，覆盖隐藏地雷防守、四步战斗链和工兵吃旗；原版失败、修改后通过。通道数量没有变化，语义版本提升到 3；带明确旧语义版本的 checkpoint 会被拒绝，无版本旧权重仍按现有兼容策略提示后允许加载，不能作为等价续训。

## CPU 计时与限制

macOS ARM CPU、Python 3.12.4、NumPy 2.4.4。固定三个随机种子，每个 128 步，共 384 个 DARK 事件：319 MOVE、25 EAT、30 KILLED、10 BOMB。所有运行 trace SHA256 相同，为 `ac031f4648dc57ba182a3ed1dc7cf5fe9a843d08c02960fc12a4b74f8da91a33`。

计时包括 state.step（含状态克隆）、四方 belief.update、四方 observation.build。不包括合法走法生成、样本预生成、belief 深拷贝、策略网络、GPU 或完整训练。每轮报告逐步平均值，再取重复轮次中位数；原版与修改版按 A1/B1/B2/A2 交替运行，各三轮。

| 微秒/环境步 | A1 原版 | B1 修改 | B2 修改 | A2 原版 |
|---|---:|---:|---:|---:|
| 状态推进 | 64.73 | 72.46 | 76.80 | 74.22 |
| 四方信念更新 | 59.22 | 29.24 | 30.51 | 64.76 |
| 四方观察构建 | 1973.07 | 1983.38 | 2014.39 | 2043.83 |

两次同版本结果取平均后，信念更新约 61.99→29.87 微秒，减少约 52%。观察构建约 2008.45→1998.88 微秒，差异很小。各步骤中位数相加再取版本平均，约 2139.92→2103.39 微秒，名义差约 1.7%；这不是直接测得的整段耗时，也没有统计显著性证明，不能声称训练整体加速。状态推进计时还受到主机负载漂移影响。

初始非交替五轮测试出现很大波动（before 观察约 1995 微秒，after 约 3415 微秒），已原样保留 before.json/after.json，不以交替结果隐瞒这组异常，也不据异常声称确定退化。交替测量支持局部更新减负，但不支持强的整体吞吐结论。

独立 cProfile 记录中，原版观察构建累计约 952.75ms，其中 _write_combat_memory 约 598.04ms，即约 63%。profile 含额外采样开销，仅用于定位相对热点，不能与上述计时相加。公开身份应用与地雷判断累计时间低于这一 CPU 流程的几个百分点，且函数包含关系存在重叠。

## 特征和内存

战斗记忆占 156/317 个空间通道，约 49.2%。单观察者完整 float32 平面为 366452 字节，其中战斗记忆平面为 180336 字节。反向吃子关系单组 60 通道，是首要消融候选；其次是类型存在、类型计数与受害槽位的重复表示。尚未测量每组独立耗时，也未证明它们对棋力无益。

16 个 CombatMemory 状态数组合计每环境 30720 字节，即 30 KiB；compact history 每帧保留四观察者记录。在 N=128、T=512 的配置示例下，仅 CM 历史静态容量为 1.875 GiB。这是依据布局计算的容量，不是当前 GPU 已分配/峰值显存测量；不能直接等同可节省内存，删减通道也不会自动删除对应历史数组。

可选 BeliefNet 刷新涉及额外网络推断、CPU/GPU 传输和 belief 上传，不在本次计时中。源码路径需要进一步核实公开硬知识保留与坐标契约；本次未端到端复现该分支的问题，未据此删除模型或修改训练开关。

## 最终验证与交付边界

- 全套本地测试：**1288 passed、162 skipped、2 warnings，94.53 秒**。跳过项涉及 CUDA/可选运行环境，详情在 pytest-full.log；不能解释为全部设备路径已通过。
- 固定原版上的三个新增合法棋局反例：**3 个预期断言失败**，见 baseline-counterexamples.log；修改版均通过。
- 12 个观察 golden 哈希已按明确改变的军阶语义重新生成。golden 是漂移检测，不替代三个独立反例。
- CUDA 源码已同步修改，但本机缺少可执行验证条件：CUDA 编译、原生设备一致性、compact-history 重建仍未验证。
- 没有运行新训练、策略强度消融或 GPU 性能基准；没有证明删去大特征组后棋力保持不变。
- ABBA 测量之后的 CPU 文件变化仅为文档字符串/注释纠正；最终源码哈希与运行时哈希分别记录，不把未提交的基线 HEAD 当作修改版身份。

建议下一轮实验先单独消融 60 通道反向关系，再消融重复的类型/计数/槽位表示；同时比较吞吐、显存和固定对手评估。该项是建议，本次没有提交计算作业或改变预算。可选神经信念刷新需先做专项正确性验证。
