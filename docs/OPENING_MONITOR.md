# 从零训练与首步分布监控

走棋网络与布阵网络均随机初始化，两个优化器重新创建，对局计数从零开始

本轮目标为 1,000 万个完整四人对局，每 1 万局保存 checkpoint，每 10 万局进行正式对战，使用一个 V100 任务，不设置人为训练时间上限

## 探索设置

使用 `configs/v100_facts_scratch_opening.yaml`，保留 317 通道事实输入、零全局输入、DARK 模式、完整对局胜负奖励和布阵训练

取消优势筛选，让所有有效策略样本参与策略、价值和熵损失

熵正则权重由 0.03 调整为固定 0.1，作为本轮起始设置，采样仍使用网络实际输出的分布

## 首步分布

训练开始前记录初始分布，每完成 1,000 局重新检测

每次检测包含两组独立合法随机布阵，每组 128 套完整棋盘、四个座位，共 512 个首步决策

一组固定种子用于跨 checkpoint 比较，另一组每次换新种子

检测计算完整策略概率，将所有目标格的概率按起点求和，得到选子分布

地雷、军旗、大本营和道路阻挡统一通过真实合法动作判断，某个起点的平均概率仅在该起点可以移动的样本中计算

记录每个位置的可动样本数、条件平均概率、全局平均概率、每个局面的最大选子概率和归一化选子熵

归一化选子熵为选子熵除以该局面可动棋子数的对数，仅统计至少四颗棋子可动的局面

## 坍缩判定与处理

初始工程阈值为同一位置的条件平均选子概率达到 95%，同时平均归一化选子熵不高于 0.2，该位置至少有 64 个可动样本

固定组与新种子组须同时触发且指向同一位置，连续三次检测满足后判定坍缩

触发时立即保存 checkpoint、完整分布和 `opening_collapse.json`，将 `training_result.json` 标记为 `opening_collapse` 并停止该次训练

该阈值用于发现跨多种布阵持续选择同一位置的训练异常，不要求每个局面均匀选择棋子

## 实现与复现

检测使用独立 CUDA 棋盘，模型以评估模式计算概率，传入指定合法动作以避免随机采样

检测前后恢复 Python、NumPy、CPU 和 CUDA 随机状态及模型训练模式，保持训练棋盘和布阵池

检测只在对局数到达检测节点时执行，按批次推理，不增加逐步训练回调

checkpoint 保留检测次数、下次检测局数、连续异常次数和上次完整结果，恢复训练继续原有监控进度

首步分布检测属于训练健康检查，正式棋力验收继续使用完整对局胜率
