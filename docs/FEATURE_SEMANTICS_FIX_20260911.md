# 特征语义与暗棋信息边界修复（2026-09-11）

基线：`b3476b1bd9fcf8a96deac5c1a2b42546d6097ad3`。
分支：`fix/feature-semantics-20260911`。

## 已复现的问题与修复

1. **CPU 工兵推断读取隐藏地雷真值。** 原 `BeliefTensor.update` 根据真实被吃棋种判断工兵，没有要求观察者已知被吃的是地雷。现在要求防守方的事前 belief 为地雷 one-hot；仍保留吃已知地雷时的合法推断。原有已知地雷测试继续通过。
2. **死亡原因特征泄漏隐藏防守棋种。** 同一攻击者分别撞上隐藏地雷、较强普通棋，公开结果都是 KILLED，原特征却分别点亮不同通道。CPU/CUDA 在 DARK、HALF_DARK 下统一输出非同归于尽/保留零通道/同归于尽；BRIGHT 保留真实分类。GameState 内部死亡原因未改，回放仍可保存真实原因。没有保存事前知识的逐观察者死亡原因，因此隐藏模式采取保守公共编码。
3. **CPU 与 CUDA 的全局剩余数量语义不同。** CPU 曾输出内部未揭示库存计数，CUDA 输出存活棋子的 belief 质量总和。现在 CPU 对齐 CUDA：每个敌方座位的 12 维值均为存活棋子的期望数量；各类型之和等于该座位存活棋子数。它不是受全局库存约束的精确后验，初始逐类型值也不保证等于标准配额。原“只检查非负”的 CUDA parity 测试已改为数值相等断言。
4. **我方地雷候选读取某一对手的私有工兵知识。** 原来任一对手知道攻击者是工兵，就被当作公开信息。CPU/CUDA 改为两个对手均知道才用于这个公共投影。真实成对状态测试要求完整 spatial/global 相等，不只检查某一通道；另有公共工兵知识仍能消除候选的正向测试。
5. **训练与评估可见模式不同。** GPU 原生训练为 DARK，而 CPU 训练/评估默认 HALF_DARK。现在训练配置明确记录 `env.show_mode: DARK`，训练入口和随机对手/双策略评估显式使用 DARK。当前训练入口只接受 DARK；底层 CPU 棋局和 GPU 观察构建器仍可支持其他模式。原生 GpuRollout 的 belief 只实现 DARK，因此它现在会在分配设备前拒绝其他模式，避免把不支持的模式当成成功运行。
6. **CUDA 空 belief 修复分支使用了半暗棋规则。** 初始化只公开自己的棋子，但 I5 空条目回填曾把队友也填成真值 one-hot。已改为只允许自己棋子的真值回填，与 DARK 初始化一致。新增了强制清空 posterior 后执行原生设备 step/update 的回归测试；它需要 CUDA 实机执行。

## 权重与历史特征

输入宽度仍为 317 个空间通道、28 个全局维度，没有增添特征或改网络结构，但以上修改改变了部分通道语义。新 checkpoint metadata 记录 `observation_semantics_version=1`；明确版本不一致会拒绝加载。旧 checkpoint 没有版本字段时仍允许形状兼容的权重加载，但发出明确提示：这不是原训练运行的等价恢复。不能据此把旧评估与新评估直接比较，也没有重写或覆盖旧权重。

12 个观察 golden 场景按新定义重新生成；这些哈希用于后续检测漂移，不替代信息边界断言。compact-history 重建读取相同 CUDA 观察代码，历史重建的 GPU 回归仍需实机执行。

## 验证与边界

对未修改的 b3476b1 基线运行四个针对性测试，四项全部失败；相同测试在修复分支通过。它们覆盖隐藏地雷推断、私有死亡原因、live belief 库存和对手私有工兵知识泄漏。

本地完整测试：1276 passed、161 skipped、0 failed（85.39 秒）；最终补充回归组：34 passed。两个 warning 均是对旧权重语义未标注的预期提示。补充组含最后添加的公共工兵知识正向测试；完整套件的统计不重复包含该新增用例。日志见交付目录。当前 macOS 没有 CUDA 扩展/NVIDIA GPU，CUDA 编译、原生 belief 回填、GPU 观察一致性以及 compact-history 实机回归不能算通过。此次没有启动新训练或覆盖既有训练结果。此前 b3476b1 的 V100 验证不能作为本次修改的验证证据。

固定归一化尺度、保留通道和现有概率先验属于设计选择；本次没有据此扩展网络或增加新特征。剩余设计质量与策略强度需要独立实验，不由这些单元测试证明。
