用户已选择新模型不使用 28 维全局摘要。设置 `net.use_global_summary: false` 后，行棋网络使用可学习的 CLS token，通过注意力从空间特征汇聚信息；不创建 `global_proj`。同一选项传入训练环境和 rollout 缓存，CPU 构建器跳过摘要计算、全局数组末维为 0，缓存与传输没有这 28 个数。CUDA 代码对单席、全席及历史重建关闭 global 缓冲分配、累加与 atomicAdd；目标 GPU 上的编译及运行验证尚待执行。

新架构元信息是 `junqi.graph317.cls.v1`、`observation_global_dims=0`；原模型仍为 `junqi.graph317.v1`、28 维。配置字段缺失时默认旧架构，以正确加载历史文件。新实验显式关闭摘要。

BeliefNet 可学习暗子身份概率，行棋网络从逐格概率和其它空间信息中学习兵力汇聚与决策。公开亮旗状态仍保留在空间通道中。取消 28 维并不要求删除身份概率、亮旗通道或规则硬约束，也没有新增一个预测 28 维摘要的神经网络头。

候选配置 `configs/v100_spatial_belief.yaml` 开启小型 BeliefNet、规则支持约束、预热及受限发布；`configs/v100_spatial_rules.yaml` 是同一无摘要架构的规则概率对照。两者默认从头初始化、使用 FP32，尚未远程运行。BeliefNet 与 PPO 使用各自的损失和优化器，通过冻结发布的概率连接；没有新增联合反向传播目标。

训练中的 GPU 评估入口已接收准备好的 BeliefNet。预测按配置的步数间隔刷新，仅发布到被评估策略所在团队的观察者；对手继续使用自己的规则概率，避免把候选模型的推断写给旧 N/M/R。交换团队时同步切换观察者。记录是否运行了神经推断及刷新频率。CPU 规则评估仍受支持；请求神经发布时要求 GPU 后端，防止静默省略 BeliefNet。命令行独立评估若只加载纯行棋导出文件，则仍是规则概率评估；联合推断需显式传入同一个已训练 BeliefNet 和发布设置。

`migrate_policy_without_global_summary` 可保留原 N/M/R 的共享权重，将原投影偏置作为 CLS 初值。迁移后与旧模型的全局输入置零行为一致，需要训练适应；旧优化器、计数和实验不会恢复。初始化文件不包含 BeliefNet，不能当成已训练的联合模型。`init_policy` 加载同架构行棋权重后使用新优化器和新计数，与 `resume` 互斥。

## 架构与旧模型影响（2026-10-01 补充）

三份模型均包含 `global_proj.weight`，形状为 `(128, 28)`，全部 3,584 个权重非零。空间特征编码成 129 个棋盘格 token，28 维全局向量经线性层编码成一个 CLS token；合并后的 130 个 token 一起进入 Transformer。动作头读取更新后的棋盘格 token，价值头读取更新后的 CLS。因此这条路径同时可能影响动作概率与局面价值。

可以保留 129 个格子、Transformer、动作头、价值头和 CLS 汇聚位置，将 `Linear(28,128)` 换成一个可学习的 128 维 CLS 初始向量。线性层原有 3,584 个矩阵权重加 128 个偏置，共 3,712 个参数；换成 128 参数的向量后净减 3,584 个参数，占 N/M/R 总参数约 0.38%。Transformer 序列长度仍是 130，不能据此宣称整体吞吐显著提高。

完整清理还需适配观测生成、rollout 缓存、policy/value 调用接口、checkpoint 架构与全局维度元信息。若同时取消 CLS，价值头的汇聚方式也要重设计。仅让外部不再传 28 个数、在适配层从 317 通道重建它们，可以沿用原权重；这只整理了接口，模型仍消费该汇总。

本次 CPU FP32 诊断复用原 8 个玩家视角局面、已导出的 N/M/R 权重以及原合法动作掩码。保持所有空间特征和权重，将全局输入置零；此时旧全局线性层输出为固定偏置，近似检查切断数量汇总输入对已训练网络的直接作用，并非从头训练新架构的消融结果。

| 模型 | 平均动作分布 KL，原模型相对置零模型（nats） | 贪心动作变化 | 价值类别概率的最大绝对变化 |
|---|---:|---:|---:|
| N | 0.008533 | 0/8 | 0.918914 |
| M | 0.010153 | 0/8 | 0.919178 |
| R | 0.000265 | 0/8 | 0.925519 |

这些数值只表明旧模型的输出确实依赖此输入。概率变化包含分类价值头的任一类别，并非胜率变化；本次没有对局、重新训练或 GPU 吞吐验证，不能推断取消输入后训练出的模型棋力如何。用空间概率求和重建全局数的对照中，合法动作 log-prob 最大差异约 `3.8e-5`、价值 log-prob 最大差异约 `4.3e-6`，体现浮点求和路径变化。

## 结论

当前 28 维全局输入全部能够从同一次观测的空间特征确定性地重建，没有增加独立的局面信息。它是一组显式汇总，是否有助于学习效率或最终棋力尚未做消融验证。信息可重建不能证明现有网络删除该输入后行为不变。

| 全局维度（从 0 开始） | 定义 | 空间来源 | 重建操作 |
|---|---|---|---|
| 0–11 | 左侧敌方 12 种棋子的存活数量期望 | `belief_left_side` 的 12 个概率通道 | 对每个通道的棋盘位置求和 |
| 12–23 | 右侧敌方 12 种棋子的存活数量期望 | `belief_right_side` 的 12 个概率通道 | 同上 |
| 24–27 | 自己、队友、左敌、右敌的亮旗状态 | `flag_revealed` 的 4 个常量通道 | 每个通道取一个位置的值 |

两个身份概率组只在对应一方的存活棋子位置非零，所以求和不会包含空格或另一方棋子。概率来自该玩家的信息状态，数量期望不是读取敌方未公开的真实身份。常量亮旗通道填满整个 17×17 编码平面；亮旗与军旗被吃掉是不同的状态。

CPU 构建器的空间身份概率和全局数量都读取 `belief.probs_arr`。CUDA 构建器也在写空间概率时对同一 `s_bel_obs` 累加。两种求和顺序可能产生 FP32 舍入差异，重建等价按数值容差比较，不能保证逐位相等。

## BeliefTensor 与 BeliefNet 的职责

以下是旧实现的职责审计。2026-10-01 用户进一步决定：新模型移除规则概率，BeliefNet 直接从事实学习。这里描述的规则分布、混合及 KL 限制不再属于新设计；见 [修订方案](JOINT_BELIEF_REVIEW_20261001.md)。2026-10-02 已新增 [事实输入策略路径](FACTS_ONLY_TRAINING_20261002.md)；本表继续描述旧适配器，不能当作新实验的输入契约。

| 组件 | 职责 | 与 28 维的关系 |
|---|---|---|
| 规则推断 / `BeliefTensor` | 用可见信息、走棋和战斗证据维护每枚棋子的身份概率 | 已能提供前 24 维的基础数据 |
| 可选的 `BeliefNet` | 从玩家视角观测预测逐格的 12 类身份分布 | 改善概率估计后，可用同一求和操作生成前 24 维 |
| 确定性汇总 | 将存活暗子的身份概率按敌方、类型求和 | 完成前 24 维的计算，无须神经网络 |
| 公开亮旗状态 | 读取已发生的规则事件 | 直接给出后 4 维，无须学习 |

当前 `BeliefNet.forward` 接收可选 `obs_global` 参数，但明确执行 `del obs_global`，没有使用这 28 维；其实际输入通道数由 `OBS_CHANNELS` 校验，目前为 317。该模块的旧版 256 通道说明已经更新。

网络输出是 `(B, 289, 12)` 的原始 logits/log-softmax；后续调用者负责 softmax、按规则支持约束、可选混合与 KL 限制，以及存活敌方掩码。不能直接对未约束的全部 289 格预测求和，否则会把空格、己方和非棋盘位置计入兵力。

若启用神经推断，先发布约束后的身份概率，再从同一版本概率构建空间通道和数量汇总。不能让空间特征用神经概率、全局数量仍用旧规则概率。规则概率可以作为独立的约束来源，但必须明确其与最终发布概率的区别。

三份真实 N/M/R checkpoint 均保存 `belief.enabled=false`，也没有保存 BeliefNet 状态。因此当前模型的“belief 特征”是规则概率，并不表示已有一个训练好的 BeliefNet 正在运行。

## 整理方案

1. 将前 24 维登记为身份概率的派生汇总，将后 4 维登记为公开状态的重复编码；各自只有一个语义来源。CPU/CUDA 可以选择适合自身的融合计算方式，无须强制重新扫描完整张量。
2. 模型输入契约应分别声明：需要哪些空间通道、需要哪些汇总，以及概率提供者是否包含 BeliefNet。是否计算汇总和是否运行 BeliefNet 应为不同的选项。
3. 原始 N/M/R 继续沿用现有 317+28 契约，以便恢复原权重与优化器；从空间输入重建全局向量可作为一致性校验或兼容适配方式。新模型可用 `net.use_global_summary=false` 关闭全局输入。
4. 对新模型做保持 317 通道的受控对照：一组保留 28 维汇总；另一组以可学习的汇总 token 接收棋盘信息，不注入 28 维。价值头仍需有汇总表示，不能只删除 CLS token。比较训练预算、种子、对手一致的棋力结果与目标 GPU 吞吐。
5. 删除 28 维或改变全局 token 处理属于新架构契约；应登记新的架构 ID/元信息并显式迁移或从头训练。直接删除 `global_proj`、向旧模型传全零，都会改变旧 checkpoint 的行为。无汇总模型的表现不能凭信息可重建而推定等价。

FP32 下每个玩家视角的 28 个数占 112 字节；317×17×17 空间数组占 366,452 字节。全局输入本身约为空间数组的 0.031%。这是原始输入体积比较，不代表实际训练显存比例或实测耗时；当前 CUDA 数量汇总含 atomicAdd，性能取舍应以 V100 基准为准。
